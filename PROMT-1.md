Задача: переработать верхнюю панель фильтрации каталога услуг и добавить раскрывающийся поиск.

Работаем в существующем проекте home/ava/king. Не нужно переписывать каталог с нуля и ненуджно тратитть лишние кредиты на изучение полного проекта.

Рабочаие длерриктории которые тебе нужны
1 - king/frontend/src/pages/catalog ( catalog.jsx, catalog.css )
2 - king/frontend/src/assets/icons

Перед внесением изменений сначала изучи текущую реализацию страницы каталога:
- найди компонент каталога;
- найди компонент/блок с кнопками социальных сетей;
- разберись, как сейчас работает фильтрация услуг;
- найди кнопку «ВСЁ»;
- определи, где хранится активный фильтр;
- посмотри существующие стили, размеры кнопок, border-radius, hover/active состояния и адаптивность.

Новые элементы должны полностью соответствовать текущему дизайну проекта.

## 1. Убрать кнопку «ВСЁ»

Сейчас в панели рядом с кнопками социальных сетей находится первая кнопка:

«ВСЁ»

Её необходимо полностью убрать из интерфейса.

При этом функциональность отображения всех услуг должна сохраниться.

После загрузки страницы каталога все услуги должны отображаться автоматически по умолчанию.

То есть логика должна быть следующей:

- пользователь открывает каталог;
- никакую кнопку «ВСЁ» нажимать не нужно;
- сразу отображаются все услуги;
- если пользователь выбирает конкретную социальную сеть — отображаются услуги только этой социальной сети.

Если пользователь впоследствии каким-либо предусмотренным интерфейсом сбрасывает фильтр, снова должны отображаться все услуги.

Не использовать кнопку «ВСЁ» как скрытый элемент — убрать её из интерфейса полностью.

---

## 2. Добавить кнопку поиска

После последней кнопки социальной сети, с правой стороны панели, необходимо добавить кнопку поиска.

Для иконки использовать существующий файл:

assets/icons/search.png

Не создавай новую SVG-иконку и не используй стороннюю библиотеку, если в этом нет необходимости.

В закрытом состоянии поиск должен выглядеть как компактная кнопка в одном стиле с существующей панелью социальных сетей.

---

## 3. Поведение поиска

По умолчанию:

[ соцсеть ][ соцсеть ][ соцсеть ][ соцсеть ] ... [ 🔍 ]

Когда пользователь нажимает кнопку поиска, должна появляться поисковая панель.

Важно:

панель должна раскрываться СПРАВА НАЛЕВО.

То есть кнопка поиска находится справа, а после нажатия поисковая строка расширяется влево.

При раскрытии она должна перекрывать кнопки социальных сетей поверх них.

Социальные сети не нужно физически удалять или сдвигать.

Поисковая панель должна находиться поверх них через корректное позиционирование/z-index.

В полностью раскрытом состоянии поисковая строка должна занимать практически всю ширину блока фильтров — от правого края до начала панели социальных сетей / левого края контейнера.

Пример:

До нажатия:

[ VK ][ TG ][ YouTube ][ TikTok ][ Instagram ] [ 🔍 ]

После нажатия:

[ 🔍   Введите запрос                              × ]

То есть раскрытый поиск полностью закрывает кнопки социальных сетей.

---

## 4. Содержимое поисковой панели

В раскрытом состоянии внутри панели должно находиться:

Слева:
- иконка поиска search.png.

После иконки:
- input.

Placeholder:

Введите запрос

Справа:
- кнопка-крестик закрытия.

Пример структуры:

[ 🔍 | Введите запрос                              × ]

Поле должно выглядеть минималистично.

Не делать отдельную тяжёлую форму или большую карточку.

Это должна быть единая компактная панель.

---

## 5. Закрытие поиска

При нажатии на крестик:

- поисковая строка очищается;
- поиск закрывается;
- панель плавно сворачивается обратно вправо;
- снова становятся видны кнопки социальных сетей;
- справа остаётся обычная кнопка поиска.

То есть обратная анимация:

[ 🔍   Введите запрос                         × ]

→

[ VK ][ TG ][ YouTube ][ TikTok ] ... [ 🔍 ]

---

## 6. Анимация

Раскрытие и закрытие должно быть плавным.

Не делай резкого появления через display: none / display: block, если это мешает анимации.

Используй подходящую CSS-анимацию через:

- width / max-width;
- transform;
- opacity;

или другой аккуратный вариант.

Продолжительность ориентировочно:

200–300ms.

Без bounce-анимаций и лишних эффектов.

Стиль спокойный и минималистичный.

---

## 7. Поиск услуг

Строка должна реально фильтровать каталог.

Поиск должен выполняться по существующим данным услуг.

Минимум искать по:

- названию услуги;
- названию платформы / социальной сети;
- другим текстовым полям услуги, если они уже есть в модели данных и логично подходят для поиска.

Поиск:
- регистронезависимый;
- обновляет список по мере ввода;
- не требует нажатия Enter.

Например:

"telegram"
"просмотры"
"подписчики"
"youtube"

должны фильтровать подходящие услуги.

---

## 8. Совместная работа поиска и фильтра социальных сетей

Не ломай существующую фильтрацию.

Логика должна быть предсказуемой.

По умолчанию:

selectedPlatform = null

или эквивалентное состояние, означающее:

показывать все услуги.

Если выбрана социальная сеть:

показываем услуги этой социальной сети.

Если дополнительно введён поисковый запрос:

сначала учитывается выбранная социальная сеть, затем поисковый запрос.

Пример:

выбран Telegram
+
введено "подписчики"

→ показываем только услуги Telegram, подходящие под запрос "подписчики".

Если поиск открыт без выбранной социальной сети:

поиск выполняется по всем услугам.

Очень важно сохранить существующий стиль проекта.

Не создавай новый визуальный стиль.

Используй существующие:
- цвета;
- фон;
- border;
- border-radius;
- размеры;
- высоту элементов;
- шрифты;
- hover;
- transition;
- spacing.

Поисковая кнопка должна восприниматься как часть существующего ряда социальных сетей.

Раскрытая панель также должна выглядеть частью текущего интерфейса, а не сторонним input.

Особенно проследи за:
- одинаковой высотой кнопок;
- вертикальным центрированием иконки;
- размером search.png;
- положением крестика;
- внутренними отступами;
- отсутствием скачков layout.

---

## 10. Адаптивность

Проверь работу на desktop и мобильных разрешениях.

На небольшом экране раскрытая строка поиска должна занимать доступную ширину контейнера и не выходить за экран.

Не должно появляться:
- горизонтального скролла;
- обрезанного крестика;
- наложения элементов за пределами контейнера.

---

Но только если это соответствует существующей архитектуре.

Не проводить несвязанный рефакторинг проекта.
